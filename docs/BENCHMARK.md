# Проверка точности

Документ описывает методику проверки и воспроизводимые сценарии. Результаты конкретных
прогонов фиксируются в отчётах и пересматриваются при изменении движка счёта.

## Принцип сравнения

Репорты сравниваются **по колонке `File name`**, а не построчно: MFT-режим и обход каталогов
выдают строки в разном порядке (порядок записей MFT против алфавитного обхода). Для каждой
пары строк сверяются `Size`, `On disk`, `Modified`, `Attributes`, `Files`, `Folders` и
дополнительные поля формата. `FREESPACE`/`USEDSPACE` в строке корня исключаются: они
показывают состояние тома на момент скана и естественно меняются между прогонами.

## Сверка двух режимов сбора

```powershell
pwsh -NoProfile -File .\scripts\verify-methods.ps1 `
  -MftCsv C:\tmp\Report_ADM_MFT.csv `
  -WalkCsv C:\tmp\Report_STD_FIXED.csv
```

Скрипт печатает число строк, дубли, различающиеся пути и количество расхождений по каждой
колонке; `RESULT: OK` означает полное совпадение. Контрольный прогон от 24.11.2026:
73 524 строки, 0 расхождений во всех 13 значимых колонках.

Этот же сценарий ловит регрессии в двух тонких местах:

- резидентные файлы: `On disk` должен быть 0, а не секторный `AllocationSize`;
- имя корня: `Path.GetFileName`, а не полный путь.

## Сверка с внешним эталоном

```powershell
# экспорт эталона и наш headless-экспорт, затем:
pwsh -NoProfile -File .\scripts\verify-external.ps1 `
  -ExternalCsv C:\tmp\external.csv -DmCsv C:\tmp\Report_ADM_MFT.csv
```

Скрипт читает эталон позиционно (у внешнего экспортера есть строка-баннера и локализованные
заголовки) и сравнивает первые семь колонок. Ключ `-IgnoreModified` исключает даты: источник
дат в WinDiskMap — `$STANDARD_INFORMATION`, тогда как внешние экспортеры иногда берут
`$FILE_NAME`, поэтому расхождения в этой колонке не считаются ошибкой счёта.

## Пофайловая сверка

```powershell
pwsh -NoProfile -File .\scripts\compare-reports.ps1 `
  -ExternalCsv C:\tmp\external.csv -DmCsv C:\tmp\ours.csv
```

Скрипт нормализует известные особенности внешнего экспорта (точка в конце имени без
расширения, отсутствие reparse-папок) и печатает missing/extra/размеры/итог/папки/время.
Оба CSV должны быть в текущем combined-формате: разделитель `,`, UTF-8, английские заголовки
у WinDiskMap.

## Контрольный путь

`C:\Windows` (NTFS): около 197 558 папок, 226 958 файлов, 56 146 966 797 байт файловых данных.
Для воспроизводимости закройте все процессы, изменяющие файлы, и снимайте экспорт после стабилизации тома:
живые ETW-логи и служебные JSON дают «лишние» файлы при последовательных сканах.

## Оговорки

- Hardlink учитывается в каждом каталоге-владельце: сумма по дереву больше «уникальных» байтов
  тома. Это осознанная семантика подсчёта, а не ошибка.
- Reparse-папки видны в дереве с размером 0, но не обходятся; внешние экспортеры могут не
  выгружать их вовсе.
- Большие CSV (десятки мегабайт) в git не коммитятся — они остаются на машине разработчика.
