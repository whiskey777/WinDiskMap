# DiskMap

Консольный анализатор занятого места на диске — аналог WizTree/TreeSize без GUI.
Точность важнее скорости: цифры сверены с WizTree пофайлово, расхождений нет.

Один exe в трёх ролях: **локальный сканер**, **агент удалённого скана**, **хост удалённого скана**.

## Возможности

### Локальный скан (Фаза 1)

- **TUI открывается сразу**, дерево пополняется по мере обхода. Во время скана в шапке —
  фаза и счётчики, без путей текущих каталогов. После выхода экран очищается, Ctrl+C
  восстанавливает цвета, курсор и режим мыши.
- **MFT-режим** — прямое чтение `$MFT` (как у WizTree), требует администратора и локального
  NTFS. При любой ошибке причина пишется в примечание/журнал, скан продолжается обходом
  каталогов. `$MFT` входит в размер корня тома — так же у WizTree.
- **Обход каталогов** — портативный фолбэк: без админа, UNC-пути, не-NTFS. Чтение напрямую
  через `FindFirstFileExW` (`FindExInfoBasic`, без DOS 8.3); обход распараллелен, но дерево
  мутирует один поток-сборщик — цифры не зависят от числа потоков.
- **Сетевые пути (UNC)** — сканируются обходом, MFT для шары недоступен. Если корень шары
  недоступен, выводится внятная ошибка с подсказкой про `net use`.
- **Цвета**: папки — голубой, файлы — белый, `.tmp/.temp/.partial` и папки Temp — жёлтый,
  дампы (`.dmp/.hdmp/.mdmp`, CrashDumps/WER) — пурпурный.
- **Мышь (SGR)**: колесо — прокрутка, левый клик — курсор + раскрыть/свернуть папку.
- **Два языка**: ru включается только при русском языке интерфейса ОС, иначе en.
  Переопределение: `--lang ru|en`.
- **CSV**: UTF-8 с BOM (Excel), разделитель `;`, потоковая запись; `--depth`,
  `--only dirs|files|tmp|dumps`, `--details`.
- **Режимы вывода**: TUI (по умолчанию), `--headless` (прогресс и отчёт в stdout, работает
  при перенаправлении), `--log <файл>` (журнал с таймстемпами). Комбинируются.

### Удалённый скан по WinRM (Фаза 2)

- `DiskMap --remote hostB --path C:\Windows` — агент (`net48\DiskMap.exe`) копируется на
  удалённый хост через `Copy-Item -ToSession`, сканирует **локальный** путь хоста и шлёт
  результаты обратно потоком NDJSON; TUI и CSV строятся локально **живьём**.
- Агент использует тот же движок: MFT под админом на локальном NTFS, иначе обход каталогов.
  Цифры совпадают с локальным сканом байт-в-байт.
- `C:\Windows` на хосте отображается в дереве как `\\hostB\C$\Windows`.
- `--agent-local` — отладка протокола через локальный дочерний процесс, без WinRM.
- Подробности и чеклист настройки: [docs/REMOTE-SETUP.md](docs/REMOTE-SETUP.md),
  формат и архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Сборка

```powershell
.\scripts\build.ps1            # Release, net8.0 + net48
```

или вручную:

```
dotnet build src\DiskMap\DiskMap.csproj -c Release
```

Результат:

| Файл | Назначение |
|---|---|
| `src\DiskMap\bin\Release\net8.0\DiskMap.dll` | основной запуск: `dotnet DiskMap.dll ...` |
| `src\DiskMap\bin\Release\net48\DiskMap.exe` | Windows .NET Framework 4.8; именно его копирует WinRM-агент |

Целевая платформа — Windows (P/Invoke `kernel32`/`user32`, MFT). Сборка чистая:
0 предупреждений, 0 ошибок.

## Portable-пакеты (без установки)

```powershell
.\scripts\package.ps1                  # artifacts\DiskMap-portable-net48-v1.0.0.zip (~43 КБ)
.\scripts\package.ps1 -SelfContained   # + artifacts\DiskMap-portable-win-x64-selfcontained-v1.0.0.zip (~30 МБ)
```

- **net48** — один `DiskMap.exe` + `.config`, работает на Windows 10/11/Server, где
  .NET Framework 4.8 встроен в ОС.
- **self-contained win-x64** — один `DiskMap.exe` со встроенным .NET 8, не требует
  установленного рантайма. В обоих архивах есть `README.txt`, `LICENSE.txt`, `SHA256SUMS.txt`.
- Оба варианта распаковываются в любую папку, ничего не пишут в реестр; `--help` и
  `--agent-local` проверены на обоих. Артефакты лежат в `artifacts/` и **не коммитятся**.
- EXE не подписан — в корпоративной среде возможны предупреждения SmartScreen/EDR
  (подробнее в [STATUS.md](STATUS.md)).

## Использование

```
DiskMap <путь> [опции]

  --csv <файл>       экспорт в CSV (без TUI)
  --headless         без TUI: построчный прогресс и итоговый отчёт в stdout
  --log <файл>       журнал с таймстемпами (фазы, счётчики, ошибки) для диагностики
  --details          в режиме --only dirs добавить в CSV строки каждого файла
  --depth <N>        ограничить глубину строк CSV (0 — только корень)
  --only <режим>     dirs (по умолчанию) | files | tmp | dumps
  --no-mft           отключить MFT-режим (обычный обход каталогов)
  --debug-mft <маск> дамп атрибутов записей MFT с такими именами в --log (через ';')
  --lang <ru|en>     язык интерфейса (по умолчанию — язык ОС)
  --remote <хост>    сканировать каталог на удалённом хосте через WinRM
  --remote-user <пользователь>   учётные данные WinRM (если нужны явные)
  --remote-pass <пароль>         пароль WinRM (с --remote-user)
  --agent            служебный режим агента (NDJSON в stdout); запускается хостом
  --agent-local      отладка: скан через локальный процесс-агент (без WinRM)
  --help             справка
```

Примеры:

```powershell
dotnet src\DiskMap\bin\Release\net8.0\DiskMap.dll C:\Users
dotnet src\DiskMap\bin\Release\net8.0\DiskMap.dll C:\ --csv big.csv --depth 2
dotnet src\DiskMap\bin\Release\net8.0\DiskMap.dll C:\ --headless --csv d.csv --only dumps --log m.log
dotnet src\DiskMap\bin\Release\net8.0\DiskMap.dll \\server\share --headless
dotnet src\DiskMap\bin\Release\net8.0\DiskMap.dll --remote hostB --path C:\Windows --csv remote.csv
dotnet src\DiskMap\bin\Release\net8.0\DiskMap.dll --agent-local --path C:\Windows --csv a.csv
```

Коды выхода: `0` — ок, `1` — ошибка аргументов, `2` — ошибка сканирования, `3` — нет терминала.

### Клавиши TUI

| Клавиша | Действие |
|---|---|
| ↑ ↓, PgUp/PgDn, Home/End | навигация |
| ← | свернуть папку / перейти к родителю |
| → | развернуть папку / спуститься к первому ребёнку |
| Enter | переключить свёрнутость |
| f | фильтр: только папки → папки+файлы → tmp/temp → дампы |
| s | сортировка: по размеру / по имени |
| e | экспорт дерева в CSV (`diskmap_export_<время>.csv`) |
| колесо мыши | прокрутка (SGR mouse mode) |
| клик левой | курсор на строку + раскрыть/свернуть папку |
| q, Esc | выход |

## CSV

Колонки: `Тип;Глубина;Родитель;Имя;РазмерБайт;Размер;Категория;ДоляПроцент`
(на en-ОС — английские заголовки и значения `Folder`/`File`).

- `--only dirs` (по умолчанию) — строки-агрегаты папок; с `--details` — плюс каждый файл.
- `--only files|tmp|dumps` — только файлные строки.
- `--depth N` — строки глубже N не пишутся (глубина по самой строке: файл в папке уровня N —
  строка глубины N+1).

## Семантика счёта (совместимость с WizTree)

- Логический размер файла — основной.
- Hardlink учитывается в **каждом** каталоге-владельце (отдельная запись `$FILE_NAME`).
  Несколько хардлинков в одном каталоге — разные имена, каждое считается отдельно;
  отбрасывается только DOS-алиас 8.3 при наличии длинного имени.
- Расширенные записи MFT (`$ATTRIBUTE_LIST`): `$DATA` из extension-записи побеждает
  FN-фолбэк (максимум по экстентам); FN-ссылки расширения — дополнительные hardlink-пути;
  длинное имя из расширения вытесняет DOS-алиас. Дедуп FN по паре (родитель, имя).
- Reparse/junction/symlink-папки видны в дереве с размером 0, но **не входят в счётчик**
  папок. Флаг читается и из `$FILE_NAME`, и из `$STANDARD_INFORMATION`.
- Пустая метка тома (корень без `$FILE_NAME`) обработана.
- WizTree в полном `/export` добавляет точку к именам без расширения (`SOFTWARE.`) и не
  выгружает reparse-папки — при сверке это нормализуется, а не считается расхождением.

Диагностика парсера: `--debug-mft "маска1;маска2"` вместе с `--log` пишет дамп атрибутов
записей с подстрокой в FN-имени (тип, namespace, VCN, allocated/real/init размеры).

## Проверка точности и бенчмарки

См. [docs/BENCHMARK.md](docs/BENCHMARK.md) и [verification/](verification/).
Кратко: обход каталогов на `C:\Windows` — 3.57 с против 6.64 с у WizTree; сверка CSV
пофайлово: missing 0, extra 0, расхождений размера 0, дельта TOTAL 0; MFT-режим и
удалённый агент (`--agent-local`) дают тот же результат.

## Ограничения

- Только Windows: MFT и TUI используют нативные вызовы.
- WinRM на удалённом хосте требует настройки (TrustedHosts, `Enable-PSRemoting`,
  Basic/AllowUnencrypted или Kerberos, порт 5985). См. [docs/REMOTE-SETUP.md](docs/REMOTE-SETUP.md).
- MFT-ветка агента под администратором на реальном удалённом хосте ещё не прогонялась;
  локально проверен обход каталогов. Подробности — [STATUS.md](STATUS.md).
